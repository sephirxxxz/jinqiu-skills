# 锦秋文案

将用户提供的主题与材料写成观点明确、事实可靠、普通读者能理解的文案。最终交付标题、正文和需要的逐页上图文字；上图文字仍是文字稿，不是图片制作任务。文案确认后停止，不自动进入出图或发布。

所有相对路径以本 skill 目录为基准。作品保存在用户项目或指定任务目录，不写进 skill 目录。

## 先读什么

1. 开始写稿或改稿前，完整读取 `references/writing-rules.md`。
2. 读取 `references/examples.md`，参考与当前板块、任务最接近的案例。文件末尾的“整理出的模式”是历史归纳，不是新增规范。历史案例中的铺垫、术语、标题长度、会议话术等不一定符合现行要求；规则冲突时按现行规范执行，不照抄过时写法。
3. 已有任务先读当期 `任务.md`、`文案.md` 和相关原始材料。已有结论、修改意见及确认状态不能只靠聊天记忆。不要把旧期案例的数字、事件或观点当成本期证据。

## 工作步骤

### 1. 核对本期要表达什么

- 从材料和当期记录提取主题、板块、读者、已确认结论、事实来源、已有文字及用户此次修改范围。
- 沿用已经明确的事项，不重复索要材料。只将阻塞主题或事实判断的问题合并询问，不做完整问卷。
- 没有底图、字体或尺寸不阻塞写稿；不为写文案索要这些信息。不自行编造板块定位或固定页数。
- 把事实冲突列成“原说法、来源、差异、建议”。证据不足时收窄结论或删去无依据的表述，不补造细节。

### 2. 安排正文与上图文字

- 先确定一个有材料支持的核心判断，再安排论据，而不是按会议纪要顺序复述。
- 正文给观点和线索，上图文字补事实、条件和例子，避免整段重复。
- 封面文字和正文支持同一个主题。需要小标题时统一并列或递进关系，顺序与首页对应。
- 页数按内容和已确认要求安排，不机械凑三点、四页。用户只要正文或局部改稿时，不额外生成整套配图文字。

### 3. 写稿、自查、一次交付

- 按现行规范写稿，再实际阅读检查论点、事实边界、指代、术语解释和语言节奏。
- 用代码分别统计发布标题、正文、正文加标签等附加内容的字数；含标点、不含空白，去除仅用于排版的 Markdown 标记。不要把备选标题、内部备注、待确认清单或上图文字计入发布正文，不用固定估值代替标签的实际计数。平台计数可能不同，交付时说明。
- 草稿超字数先自行精简；已确认文案需要改字时，说明具体修改并请用户确认。
- 交付第一行放发布标题，接正文、需要的逐页上图文字，最后单列字数和事实待确认项。不要把内部校对说明夹在发布正文里。
- 未获用户确认只标“待确认”；不得自行标成定稿。用户确认后保存对应版本和确认状态。

### 4. 局部修改与交接

- 用户只改一项，就只修改受影响文字，不让全文重新审批，不覆盖已确认版本。
- 文案交接以当期文件为准，明确哪一版已确认、哪些文字属于正文或哪一页，以及尚未解决的事实问题。
- 后续设计需要删改已确认文字时，返回文案修改与确认，不让视觉制作静默改字。
- 不调用视觉 skill，不制作测试图，不设置字体，不预设是否使用 Canva。出图须由用户另行要求。

## 文件记录

沿用用户指定目录；在锦秋图文项目中默认使用 `作品/<期号或主题>/`：

- `任务.md`：只记录真实存在的主题、板块、材料路径或来源、当前文案阶段、已确认事项、待解决问题和稿件路径。
- `文案.md`：标题、正文、话题标签、逐页上图文字，以及确认状态；内部备注与发布文字分开。
- `输入/`：原始材料或其路径，不覆盖原件。

已有记录中属于设计的字段保留，不擅自删除或改写；本 skill 不负责填写和验证它们。不为了文案任务新建出图目录、渲染工具或额外审批流程。

## 完成标准

- 主题和结论明确，论据支持结论；事实、引述、作者判断及推测能分清。
- 标题不超过 20 字；正文 500–600 字；发布正文含标签等附加内容不超过 1000 字。当前任务明确批准的例外单独注明。
- 普通读者能直接理解，专业词和缩写首次出现有简短说明。
- 正文与上图文字互补，没有遗漏用户指定事项，也没有从旧案例搬来本期不存在的事实。
- 交付稿件位置、实际字数、确认状态和必要的待确认项。不宣称文字已确认就等于图片可发布。
